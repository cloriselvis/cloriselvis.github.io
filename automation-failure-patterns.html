Automation reliability field notes

Green runs do not prove the business outcome happened.

Public n8n and Make threads show the same reliability gap again and again: the workflow technically runs, but rows are missing, approvals stall, queues lag, alerts flood, or retries risk duplicates.

Public failure patterns

These are paraphrased from public community threads. The point is not that every case needs a rebuild. The point is that each case needs an outcome check outside the green checkmark.

Pattern Public signal Business risk Smallest reliability check
Concurrent writes miss rows Webhook uploads append to Google Sheets; single uploads work, but bulk uploads record only some rows while executions show success. Assets, leads, orders, or form entries disappear from the operator's working sheet. Add a stable upload or item ID, compare received count to written count, and reconcile missing IDs before Sheets becomes the only record.
Approval sends but never resumes A Slack approval message is sent, but the wait node returns no usable output and the workflow stops or cancels. Lead endorsement, review, or handoff work looks initiated but never reaches the next system. Track each approval request by ID, timeout, owner, and final outcome; alert on unresolved approvals.
Queue processes hours late A Make scenario accumulates queued records and later processes them after a multi-hour delay. Time-sensitive records wait too long, so "eventually processed" is still operational failure. Measure oldest queue age and count; alert when lag exceeds the expected processing SLA.
Retry can duplicate work Google Sheets rate limits stop a workflow; the operator wants auto-restart but is worried about duplicate runs. Recovery can create duplicate rows, duplicate messages, or inconsistent downstream state. Define an idempotency key and retry cursor before auto-restarting failed or stopped runs.
Trigger fails only in production A Google Sheets trigger stops in scheduled use while manual runs still appear to work. Manual testing gives false confidence; the real scheduled workflow remains broken. Add a heartbeat for expected run time and a zero-delta check for missing downstream changes.
Error alerts become noise Repeated API failures create a flood of Slack alerts instead of one actionable incident. People learn to ignore the channel that should protect the workflow. Group errors by workflow, error class, and time window with first seen, last seen, count, and owner.

Reliability fix shape

Define the outcome

Write the business result in plain language: records appended, leads routed, approvals completed, reports delivered, invoices updated, or files processed.

Find the trust gap

Separate execution health from outcome health. A green run can still hide missing rows, late queues, empty results, or stalled approvals.

Add one proof check

Start with the smallest durable check: count, heartbeat, queue age, stable item key, unresolved approval list, or grouped error summary.
